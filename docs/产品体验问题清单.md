# 产品体验与关系澄清（入驻→门店→商品→交易）

> 更新于链路修补后。用于运营/研发对齐「应该怎样」，以及仍待排期项。

## 已澄清的关系（正确心智模型）

```text
小程序入驻 / 运营台代客入驻
        ↓ pending
商家入驻审核（通过）
        ↓ 生成 merchants
用户与门店 · 地摊 / 异业 / 供应链（一家店一条）
        ↓
门店商品维护（必须选所属门店） / 商家端「本店商品」
        ↓
C 端点餐 / 兑换 / 采购 → 支付 → 完单
```

| 后台菜单 | 绑什么 | 不绑什么 |
|----------|--------|----------|
| 商家入驻审核 | 申请单 → 通过后出门店 | 不直接写商品 |
| 地摊/异业/供应链门店 | 门店主数据 | — |
| 商品类目（按角色） | stall/cross/supply **角色** | **不是**某一家店 |
| 门店商品维护 | **某一家门店** 的商品 | 不能只填商户数字 ID |
| 全量SKU（按店） | 跨店检索/上下架 | 类目配置 |

## 本轮已修

1. 入驻列表时间：按库内 DATETIME 原样展示，避免 +8 小时错到次日  
2. 证照预览：只认图片 URL；不再把「交通银行」等文本渲成可点「附件」  
3. 平台配置菜单暂时隐藏  
4. 商品新建改为**下拉选门店**；列表展示「店名 + 门店ID」  
5. 小程序商家商品页标题改为「本店…」，标明当前门店  

## 仍不合理 / 建议排期（P0–P2）

### P0 资金与状态

- 直收联调时账本记商家应收、钱在平台号：进件完成前勿当「已到账」对外承诺  
- 积分池不足时已改为不挡支付，但「划拨不足」需运营可见告警（后台尚无红点）

### P1 信息架构

- 「门店商品维护」与「全量SKU」能力重叠：中长期可合并为一页（类型 + 门店筛选）  
- 入驻审核详情里结算卡/证照字段与微信进件字段未做「缺什么标红」清单  
- 城市关闭后存量营业门店仍在 C 端可见：需产品决定「关城是否强制歇业」

### P2 体验

- 代客入驻仍用占位证照，人工审前必须改真实材料，否则进件必失败  
- Banner / 类目 / SKU 命名历史不一致，建议统一文案规范  
- 小程序 C 端列表仍可能出现无封面空店，需「无商品不露出」规则  

## 验收口诀

1. 新店只能从入驻审核来  
2. 商品必须能说出「哪家店」  
3. 类目只按角色，不按店  
4. 证照预览必须是图，时间必须是业务当地钟点
