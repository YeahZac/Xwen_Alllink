## `INVALID_HOST`（域名已解析但仍 403）

报错：

```text
错误码 INVALID_HOST
Check domain authority failed.
```

说明：**DNS 已经指到云托管网关，但网关不认 `Host: wanye.cloud` 这个自定义域名**。  
常见原因：DNS 的 CNAME **填成了默认服务域名**，而不是控制台「自定义域名」给出的接入域名。

### 你当前 DNS（不正确）

| 主机 | 类型 | 记录值 |
|------|------|--------|
| `@` | CNAME | `alllink-server-305818-11-1467541248.sh.run.tcloudbase.com` ← **这是默认域名，不能当自定义域名 CNAME** |

证书侧已能为 `wanye.cloud` 签到证书，但网关鉴权仍失败 → 必须用控制台下发的 **tcbaccess** 类 CNAME。

### 正确改法

1. 打开 **微信云托管** → 服务 **`alllink-server`** → **自定义域名**
2. 确认列表里有 **`wanye.cloud`**，状态为「开启 / 正常」，关联服务是 `alllink-server`
3. 复制该行的 **CNAME / 接入域名**（一般类似）：
   - `wanye.cloud.tcbaccess.tencentcloudbase.com`
   - 或其它 `*.tcbaccess.tencentcloudbase.com`
4. 到 **DNSPod** 把根域 `@` 的 CNAME **改成**上面复制的值（不要再指向 `*.sh.run.tcloudbase.com`）
5. 等 1～10 分钟后验证：

```bash
dig @119.29.29.29 wanye.cloud CNAME +short
# 期望看到 *.tcbaccess.tencentcloudbase.com，而不是 sh.run.tcloudbase.com

curl -I https://wanye.cloud/api/health
# 期望 JSON code=0，而不是 INVALID_HOST
```

6. 若控制台里根本没有 `wanye.cloud`：先 **添加自定义域名** → 按提示配 CNAME → 等域名校验通过、证书就绪，再访问。

官方说明：https://docs.cloudbase.net/error-code/service/INVALID_HOST

## `admin.wanye.cloud` 现状

- DNS **已有** CNAME，能解析到云托管
- 但证书 **不包含** `admin.wanye.cloud`（浏览器会提示不安全；curl 报 SSL name mismatch）
- 若要用 admin 子域正式访问：
  1. 云托管自定义域名 **添加** `admin.wanye.cloud`（绑同一服务）
  2. 为该主机申请/绑定证书
  3. 环境变量后重新发布：
     ```text
     PUBLIC_BASE_URL=https://admin.wanye.cloud
     ADMIN_HOST=admin.wanye.cloud
     ```

未完成前，**不要**依赖 `https://admin.wanye.cloud/` 或缺失解析的 `https://wanye.cloud/`。

## 以前的 `INVALID_PATH`

若域名能解析，但页面是云托管网关 `INVALID_PATH`：说明该主机名 **未绑到服务**，或绑错服务。到自定义域名列表核对「关联服务 = alllink-server」。

参考：https://docs.cloudbase.net/error-code/service/INVALID_PATH
