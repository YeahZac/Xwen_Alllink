# 内容与运营管理 · 状态开关需求（产品说明）

> 角色：运营 / 超管  
> 范围：商品 SKU、商品目录、商品类目、Banner 运营（及同类「可上架/可展示」资源）  
> 原则：**列表内一键开关；关闭后 C 端不可见；勿再进详情改状态。**

---

## 1. 背景与问题

运营台「内容与运营管理」里，状态控制曾出现三种不一致体验：

1. **商品 SKU**：行内同时放「打开」「关闭」两个按钮，易误点、也不符合「一个开关」心智。  
2. **Banner / 部分目录**：状态只显示数字 `1`，要进「编辑」弹窗才能改，列表无法即时管控。  
3. **线上静态资源未刷新**：本地已改开关组件，云托管仍可能缓存旧 `app.js`，运营仍看到旧双按钮界面。

业务后果：下架/隐藏不及时 → C 端仍展示；操作路径长 → 运营效率低、易出错。

---

## 2. 用户目标（运营操作）

| 目标 | 说明 |
| --- | --- |
| 秒级上下架 | 在列表直接拨开关，无需打开详情 |
| 状态一眼可读 | 开=上架/展示/启用；关=下架/隐藏/停用，文案随开关变化 |
| 关了前端没有 | 关闭后消费者端、商家点餐/兑换列表均不再出现 |
| 少误操作 | 删除仍要二次确认；开关失败自动回滚勾选 |
| 权限可控 | 无编辑权的角色只读，开关 disabled |

---

## 3. 信息架构与页面规则

### 3.1 适用页面（必须列表开关）

| 页面 | 状态字段 | 开 / 关文案 | 行内操作栏仅保留 |
| --- | --- | --- | --- |
| 商品 SKU | `on_sale`（供应链用 `status`） | 上架 / 下架 | 编辑、删除 |
| 商品目录 | 同上 | 上架·启用 / 下架·停用 | 编辑、规格(地摊)、删除 |
| 商品类目 | `status` | 启用 / 停用 | 编辑、删除 |
| Banner 运营 | `status` | 展示 / 隐藏 | 编辑、删除 |

**禁止**：在「操作」列再放「打开」「关闭」两个独立按钮。

### 3.2 详情/编辑弹窗

- 仍可带状态下拉（新建时默认「开」），与列表开关同源字段。  
- **日常改状态以列表开关为准**，不强迫进详情。

### 3.3 交互细则

1. 开关为单一 `checkbox` 滑块（`.switch`），右侧短文案随状态变。  
2. 拨动后立即请求 API；成功刷新本行或整表；失败 toast + 勾选回滚。  
3. 关闭态行可浅灰（`tr.is-off`），便于扫描。  
4. 删除与开关分离：删除必须确认文案含「不可恢复」。

---

## 4. C 端可见性（硬规则）

| 资源 | 关闭后 |
| --- | --- |
| 地摊/异业商品 | 菜单、兑换列表、下单校验均不可见 / 不可买（`on_sale=1` 过滤） |
| 供应链货品 | 采购列表不可见（`status=1`） |
| Banner | `/api/banners` 仅 `status=1` 且在有效期内 |
| 类目 | 运营编辑商品时下拉仅启用类目；已下架类目名可保留历史商品上的文本，但不可新选 |
| 歇业门店 | `merchants.status≠1` 不出现在附近店列表（既有逻辑） |

验收口径：**运营把开关拨到「关」→ 强刷小程序对应页 → 该项消失；拨回「开」→ 重新出现。**

---

## 5. 接口约定

| 动作 | 方法 | 说明 |
| --- | --- | --- |
| SKU/目录上下架 | `POST /admin/ops/skus/:type/:id/open\|close` | 已有 |
| Banner 展示开关 | `PATCH /admin/banners/:id/status` `{status:0\|1}` | 列表专用，免全量保存 |
| 类目启用开关 | `PATCH /admin/goods-categories/:id/status` `{status:0\|1}` | 列表专用 |
| 全量编辑 | 原 POST/PUT 仍可用 | 含改标题、图、排序等 |

---

## 6. 发布与缓存

- 运营台 `index.html` 引用 `app.js` / `styles.css` 必须带版本 query，避免 CDN/浏览器死缓存。  
- 服务端对运营台 HTML/JS 建议短缓存或 `no-cache`。  
- **每次改运营台静态资源后必须重新发布云托管服务**，否则线上仍为旧双按钮。

---

## 7. 非目标

- 不在此需求改「审核通过/驳回」（仍用专用按钮）。  
- 不在此需求改投诉工单的「关闭工单」语义（那是工单生命周期，不是上架开关）。  
- 不做定时上下架排程 UI（Banner 已有 start/end 字段，高级排期可后置）。

---

## 8. 验收清单

- [ ] SKU 列表：仅一个上架开关 + 编辑 + 删除；无「打开/关闭」双按钮  
- [ ] 商品目录、类目、Banner：列表可直接开关  
- [ ] 关 Banner → C 端首页轮播消失  
- [ ] 关 SKU → 地摊菜单/异业兑换不再出现该品  
- [ ] 无编辑权账号开关不可点  
- [ ] 云托管发版后强制刷新运营台，UI 与本文一致
